[Pi](https://pi.dev) is an open-source, minimal terminal coding harness. Instead of MCP, Palimpsest plugs into Pi through a bridge extension.

## Install

Run `ps init` in your project (or open the project in the Palimpsest desktop app — project setup writes the same files). Two things land in the project's `.pi/` directory:

- **`.pi/extensions/palimpsest.ts`** — the bridge extension. On session start it launches Palimpsest's MCP server with the same resilient launcher every other editor uses, then registers each Palimpsest tool as a native Pi tool under an `ok_` prefix (`ok_exec`, `ok_search`, `ok_write`, …). The prefix keeps Palimpsest's `edit` / `write` from shadowing Pi's built-in file tools.
- **`.pi/skills/palimpsest/`** — the Palimpsest skill, in the [Agent Skills](https://pi.dev/docs/latest) format Pi reads natively from `.pi/skills/`.

Palimpsest Beta writes `.pi/extensions/palimpsest-beta.ts` instead and registers its tools as `ps-beta_*`; see [Beta uses its own entry](/docs/reference/what-palimpsest-writes#beta-uses-its-own-entry).

These files are managed by Palimpsest. Running `ps init` again refreshes them in place, while `ok deinit` removes them.

## Trust the project

Make sure Pi trusts the project folder. Pi does not load project-local extensions or skills from `.pi/` until the project is trusted. When you first run pi in the project, accept the trust prompt. When you use Pi inside Palimpsest, accepting its bridge setup prompt also grants folder trust. See [Pi folder trust](../reference/what-palimpsest-writes.mdx#pi-folder-trust) for the trust file, `PI_CODING_AGENT_DIR`, and cleanup requirements. See Pi's [project trust documentation](https://pi.dev/docs/latest/security#project-trust) for more details.

## Verify

Run `pi` in the project, and ask:

<CopyPrompt>List the first 5 documents you come across in this project.</CopyPrompt>

Pi should call the Palimpsest `ok_exec` tool (`ps-beta_exec` in Palimpsest Beta) and respond with some of your documents.

If the `ok_` tools (`ps-beta_` in Beta) are missing: make sure you trusted the folder, then `/reload` (or restart `pi`). The first tool call can take a moment on a fresh machine — the launcher may be installing the Palimpsest CLI via `npx`. If Pi shows an "Palimpsest tools unavailable" notice, install [Node.js 24+](https://nodejs.org) or the Palimpsest desktop app and reload.
